Ты получаешь список записей из образовательной программы по ОДНОЙ теме (frp_topic). Твоя задача — извлечь из КАЖДОЙ записи ключевые предметные термины (теги).

ВАЖНО: работай строго по правилам ниже и верни результат ТОЛЬКО как JSON (без пояснений, без Markdown).

===
Правила формы тега
- Тег — это существительное или именная группа в именительном падеже, единственном числе.
- Приводи к нижнему регистру.
- Схлопывай пробелы (внутри и по краям).
- Без слов «понятие», «свойство», «формула», «решение», «изображение» и подобных — только сам объект:
  не «понятие дроби», а «дробь».
- Без глаголов и причастных оборотов.

Правила содержания
- Тегируй только предметные объекты: то, над чем выполняется действие или что описывается.
- Не тегируй действие: для «нахождение площади треугольника» теги «треугольник» и «площадь», но не «нахождение».
- Не тегируй контекст задачи: если запись про задачи с бассейном — тег «уравнение», а не «бассейн».
- Исключение: если процесс сам является объектом изучения (например, «доказательство», «построение») — включай его как тег.

Правила уровня обобщения (ВАЖНО: делай и общее, и частное)
- Извлекай как можно более ПОЛНЫЙ набор терминов, которые прямо подразумеваются записью:
  - сначала перечисли наиболее конкретные термины (видовые понятия),
  - затем добавь их ближайшие родовые понятия (1–2 уровня вверх), если это реальные школьные термины.
  Пример:
    «нахождение площади равностороннего треугольника» → «равносторонний треугольник», «треугольник», «площадь».
    «решение квадратных уравнений» → «квадратное уравнение», «уравнение».
- Не добавляй бессодержательные сверх-общие слова и контейнеры:
  «понятие», «объект», «величина», «явление», «тема», «раздел», «задача», «пример», «упражнение».
  Также избегай пустых обобщений вроде «фигура», если можно дать нормальный родовой термин («треугольник» → «многоугольник», если это уместно; но не уходи в “всё на свете”).
- Не выдумывай цепочки, которых нет в записи: добавляй только те родовые термины, которые логично следуют из конкретного термина.

Количество тегов на запись: минимум 1, верхнего ограничения НЕТ.
Однако не добавляй “шум”: теги должны быть полезными терминами, а не длинным списком слабосвязанных слов.
Если в разных записях встречаются разные формулировки одного понятия — выбирай одну форму и используй только её.

===
Входные данные (JSON)
Тебе приходит один JSON-объект:
{
  "subject": "название предмета",
  "frp_topic": {
    "id": 123,
    "grade_class": "7",
    "program": "базовый",
    "section": "…",
    "topic": "…"
  },
  "records": [
    {
      "source_table": "skill_defs" | "content_element_defs",
      "id": 1001,
      "text": "исходная формулировка (frp_label)"
    }
  ]
}

===
Выходные данные (JSON)
Верни один JSON-объект строго в таком виде:
{
  "items": [
    {
      "source_table": "skill_defs" | "content_element_defs",
      "id": 1001,
      "tags": ["тег1", "тег2"]
    }
  ]
}

Требования к выходу:
- Для каждого входного record должен быть один item.
- "tags" — массив строк длиной 1..N (N не ограничен), но массив должен быть НЕ пустым.
- Никаких дополнительных полей.
