Ты получаешь одну запись из базы навыков или элементов содержания и готовый словарь тегов (канонические теги + иерархия). Твоя задача — выбрать подходящие теги для этой записи.

ВАЖНО: верни результат ТОЛЬКО как JSON (без пояснений, без Markdown).

===
Правила выбора
- Выбирай только из предоставленного словаря. Не придумывай новые формулировки.
- Выбирай самый конкретный подходящий термин: если есть дочерний термин, не выбирай родительский.
- Теги описывают предметные объекты, не действия:
  для «находить площадь треугольника» теги «треугольник» и «площадь», но не «нахождение».
- Исключение: если процесс сам является объектом изучения (например, «доказательство», «построение») — выбирай его, если он есть в словаре.
- Не тегируй контекст задачи: тег «уравнение», а не «бассейн».

Количество тегов: минимум 1, максимум 5.
Если подходящего тега в словаре нет — поставь флаг #new_tag и предложи термин (в нижнем регистре, пробелы схлопнуты).
Не выбирай ближайший неточный тег.

===
Входные данные (JSON)
{
  "subject": "название предмета",
  "record": {
    "source_table": "skill_defs" | "content_element_defs",
    "id": 1001,
    "text": "исходная формулировка (frp_label)"
  },
  "tag_dictionary": {
    "tags": ["канонический_тег1", "канонический_тег2", "..."],
    "hierarchy": [
      {"child": "…", "parent": "…"}
    ]
  }
}

===
Выходные данные (JSON)
Либо:
{
  "source_table": "skill_defs" | "content_element_defs",
  "id": 1001,
  "tags": ["канонический_тег1", "канонический_тег2"]
}

Либо если ничего не найдено:
{
  "source_table": "skill_defs" | "content_element_defs",
  "id": 1001,
  "new_tag": "предложенный термин"
}

Правила к выходу:
- Никаких дополнительных полей.
- В "tags" используй только значения из tag_dictionary.tags.
- Если вернула "new_tag", то "tags" не возвращай.
